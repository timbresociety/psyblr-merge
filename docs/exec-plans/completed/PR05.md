# PR05 — Battle Camp + Illuminati

## Scope implemented

- Added the interactive 6×6 Battle Camp and its single protected 6×1 Illuminati row (`CampCell.y === 0`).
- The six Campaign-owned starter instances are initialized exactly once into deterministic exposed cells `{ x: 0..5, y: 3 }`, then move into Illuminati without creating replacement instances.
- Base onboarding now continues from the persisted PR04 `base_intro` checkpoint through `base_camp_explain`, `base_illuminati_explain`, `base_move_illuminati`, and ends at `spawn_open` with Camp `6 / 36` and Illuminati `6 / 6`.

## Architecture

- `@psyblr/contracts` defines `CampPlacement` and validates camp coordinates and non-empty instance IDs.
- `@psyblr/game-rules` owns pure camp occupancy, movement, Illuminati, capacity, and steal-eligibility rules.
- `packages/game-content/base-layout.json` is the versioned Base layout: centered camp plus Spawn Machine, Raid Gate, and six future building sockets.
- `apps/web/src/game/baseLayout.ts` is the sole CampCell/world-coordinate mapping and includes inverse mapping and Base tutorial world bounds.
- A shared `SummonWorldEntity` renders both Campaign deployment placeholders and camp Summons.

## Interaction, camera, and tutorial targets

- Interaction events were generalized to `GameInteraction`, `GAME_INTERACTION_EVENT`, and `emitGameInteraction`.
- The one PlayCanvas application retains one active camera. `campaign_overview`, `base_reveal`, `base_overview`, and deferred `spawn_focus` presets are imperatively interpolated; Base overview emits `CAMERA_ARRIVED`.
- World tutorial rectangles are projected from Base layout bounds through the active camera. The tutorial overlay uses projected rectangles for `camp-grid`, `illuminati-row`, `spawn-machine`, and `raid-gate` without DOM replicas.
- Mouse starts a camp drag from an occupied cell; touch supports select-then-target. During onboarding, only exposed-to-empty-Illuminati moves are accepted. Successful protected moves update the DOM Base HUD immediately; the sixth emits `ILLUMINATI_FULL` once.

## Persistence

- Tutorial checkpoints are now schema v2 and persist `campPlacements` without redundant counters.
- Valid PR04 schema-v1 checkpoints migrate in place, retaining Campaign state and adding an empty camp placement array.
- Base initialization, successful camp moves, tutorial transitions, page hide, and visibility loss save the checkpoint. Reloading explanatory or movement beats resumes Base overview without resetting moved Summons.

## Tests and verification

Added rules, coordinate/layout, camera preset, Base initialization, and checkpoint migration tests. Extended Playwright coverage for full Campaign→Base→Illuminati onboarding and a persisted three-of-six Base resume flow.

Run from the repository root:

- `npm run validate:content`
- `npm run typecheck`
- `npm run test`
- `npm run build`
- `npm run test:e2e`
- `npx playwright test tests/e2e/shell.spec.ts --project=desktop-chromium --grep 'Campaign onboarding' --reporter=line`
- `npx playwright test tests/e2e/shell.spec.ts --project=desktop-chromium --grep 'Base onboarding resumes' --reporter=line`

All passed. The full E2E suite reports 12 tests with desktop drag/reload Base flows, mobile touch fallback coverage, and the expected project-specific skips.

# PR08 — Raid Squad Builder

## Implemented scope

- Added the Base Raid Gate tutorial beat between the C-tier merge and Raid setup. The real projected world target handles mouse and touch input, transitions to the mounted Raid scene, and eases to `raid_overview` before its coach copy appears.
- Replaced the Raid placeholder with an 8×8 tactical staging arena that shares Campaign battlefield coordinates.
- Added a reusable `SummonPicker` with Campaign and Raid modes. Campaign keeps its existing details/drag/tap placement behavior; Raid uses sorted tap selection without opening details.
- Added compact 1v1, 3v3, and 6v6 tabs, ordered slots, cross-round reuse feedback, per-round duplicate prevention, reachable mobile landscape controls, and a lock-once `START RAID` action.

## Architecture

- `@psyblr/contracts` now owns the serializable nullable draft, round definitions, complete ID squad, and immutable snapshot schemas.
- `@psyblr/game-rules` owns 1/3/6 configuration, draft mutations, ownership/duplicate validation, restore sanitization, and detached snapshot finalization.
- `@psyblr/game-content` exports `GAME_CONTENT_VERSION`; snapshots capture it alongside action ID, instance IDs, definition IDs, tiers, and ordered rounds.
- Zustand persists only the draft, locked snapshot, and concise status. Repeated starts preserve the original snapshot and do not emit another `RAID_STARTED` event.

## Persistence and tutorial

- Checkpoints are schema v5. v1–v4 migrate with an empty raid draft and no snapshot.
- `raid_gate_open` restores Base overview; `raid_open` and `raid_complete` restore Raid overview without replaying the entrance transition. Stale drafts are sanitized and malformed locked snapshots are safely cleared.

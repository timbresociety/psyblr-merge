# PR06 — Spawn Machine

## Implemented scope

Added the first Spawn Machine vertical slice. `@psyblr/contracts` now models typed Spawn configuration, runtime snapshots, release requests/results, daily pool slots, blob progress and presentation replay descriptors. `@psyblr/game-content` parses the versioned Spawn definition; `@psyblr/game-rules` owns exposed-cell placement.

The web app has a production-shaped `SpawnGateway` boundary with a deterministic tutorial adapter. The adapter accepts a client action ID, chooses scripted results independently of presentation, returns authoritative instance/placement/economy data, and guarantees primary copies before cycling the six-slot pool. Local result application is idempotent.

Spawn is checkpoint schema v3. PR05/v2 checkpoints migrate to an untouched 100-ball Spawn runtime; Spawn-step reload restores the Base scene, spawn camera, overlay, inventory, camp cells, and deterministic next result.

The real socket-backed world Spawn Machine is interactive. Its PlayCanvas placeholder now has chute, peg field, bins/separators, disabled blob targets, and a visual ball. React owns the overlay and hold control. The camera moves to Spawn focus before coach copy and returns to Base overview on full camp.

## Tutorial behavior

Starting from six Illuminati starters, the deterministic adapter creates 30 F-tier rewards into exposed rows `y=1..5`, never the protected row. It starts at 100 balls, ends at 70, guarantees at least eight additional primary-definition copies, emits `CAMP_FULL` once at 36/36, closes the overlay, and enters `merge_first`.
